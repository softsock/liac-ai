# M4.3 – Initiative & Character Continuity

Продовжуй роботу над `softsock/liac-ai` після завершеного M4.2 (`codex/m4-2-markdown-context`, коміт `bea6abc`).

**Мета – надати Liac обмежену самостійність: персонаж повинен іноді сам вирішувати, чи варто щось сказати, повернутися до попередньої теми, пожартувати або промовчати.**

Збережи нашу спрощену архітектуру: **Luna – асинхронний режисер поведінки, Nemotron – швидкий виконавець, `context.md` – спільний робочий контекст.**

Не перетворюй проєкт на складну multi-agent систему.

## 1. Спочатку досліди поточну реалізацію

Використай контекст попередньої роботи в цьому чаті.

Прочитай актуальні `AGENTS.md`, `PROJECT_BLUEPRINT.md`, `M2_IMPLEMENTATION.md`, `M4_2_IMPLEMENTATION.md` та відповідні модулі.

Особливо перевір:
- Як Luna оновлює Markdown Context.
- Як працюють Deep worker, Journal та Runtime.
- Як створюються Fast turns і відбувається streaming/cancellation.
- Як забезпечується KV cache reuse.
- Які механізми вже можна повторно використати для ініціативи.

Спочатку визнач найменший обсяг змін. Не створюй нових підсистем без конкретної потреби.

## 2. Luna керує ініціативою

Luna повинна мати можливість:

- Формувати власну цікавість до теми.
- Пам'ятати короткострокові наміри в `context.md`.
- Пропонувати повернення до незавершеної розмови.
- Придумувати конкретні жарти, запитання та коментарі.
- Вирішувати, що зараз краще нічого не говорити.
- Оновлювати або відкидати свої попередні ідеї залежно від розвитку розмови.

Не створюй окрему психологічну модель із числовими mood, curiosity, boredom або relationship scores.

Luna вже має ширший контекст і повинна самостійно оцінювати доречність поведінки.

## 3. Ініціатива через Markdown Context

Розширюй існуючий `context.md`, а не створюй паралельну систему пам'яті чи Performance Beats.

Приклад:

```markdown
## Current Situation
The user is working on Skin Creator.

## Open Threads
- The user wanted to finish the new layout.

## Suggested Threads
- If the redesign comes up again, tease them about
  releasing version 2 before version 1.

## Current Interests
- Curious whether the user finally finished the layout.

## Possible Initiative
- When the conversation naturally becomes quiet,
  consider asking whether the layout is finished.
- This is optional. Don't interrupt active work.
```

Це приклад, не обов'язкова структура.

Luna може змінювати, видаляти й переписувати ці секції. Не вводь жорсткий формат для кожного наміру.

Nemotron отримує Markdown у вже реалізованій змінній частині контексту.

## 4. Самостійне ініціювання Fast turn

Потрібна одна нова можливість: **Luna може запропонувати самостійний turn, навіть якщо користувач не надіслав нового повідомлення.**

Водночас не плутай текстову поведінкову підказку з командою на виконання.

Залиш Markdown для змісту, а для фактичного ініціювання використай найменший типізований контракт, наприклад:

- `speak` або `none`;
- конкретний намір чи тему;
- причину, прив'язану до реального контексту;
- посилання на події;
- необов'язкову мінімальну затримку й термін актуальності.

Це не повинно перетворитися на складний Beat Scheduler.

Runtime перевіряє, чи можна запускати Fast, після чого Nemotron сам генерує репліку.

**Luna пропонує зміст і можливість, Runtime контролює виконання, Nemotron відповідає за остаточне формулювання.**

## 5. Коли дозволяти ініціативу

Не запускай розмову просто тому, що минуло N секунд.

Потрібна змістовна причина, наприклад:
- Незавершене запитання чи домовленість.
- Природне продовження попередньої теми.
- Доречний жарт або спостереження.
- Короткостроковий інтерес самого персонажа.

Мінімальні правила Runtime:

- Не перебивати активний Fast stream.
- Нове повідомлення користувача має пріоритет.
- Не використовувати застарілі рішення Luna.
- Не повторювати одну й ту саму ініціативу.
- Дотримуватися простого cooldown.
- Не говорити, якщо немає релевантної причини.
- Не запускати додаткові виклики Luna лише через спрацювання таймера.

Можна використати просту перевірку готовності відкладеної ініціативи. Не потрібна універсальна scheduling framework.

Зроби автономне мовлення явно вмиканою можливістю, щоб під час тестування персонаж не починав говорити несподівано.

## 6. Автономний turn і Journal

Самостійна репліка повинна проходити через наявний Fast pipeline:

- Той самий Nemotron.
- Той самий ContextCompiler.
- Той самий streaming.
- Та сама політика KV cache.
- Той самий Event Journal.

Але автономний turn не можна записувати як вигадане повідомлення користувача.

Використай мінімальне розширення типізованих подій або входу Fast, щоб відрізняти user-initiated та character-initiated turns.

Завершена автономна репліка стає частиною канонічної історії. Luna бачить фактичний результат у наступному звичайному Deep batch.

Після перезапуску система не повинна випадково повторювати вже виконану або скасовану ініціативу.

## 7. Не втрачати природність

Це принципово важливіше за кількість автономних реплік.

Liac не повинен:
- Постійно ставити запитання заради продовження розмови.
- Повторювати однакові жарти.
- Коментувати кожну незначну подію.
- Поводитися як асистент, який безперервно пропонує допомогу.
- Механічно виконувати всі Suggested Threads.

Персонаж може бути silly, іноді нелогічним або дитячо безпосереднім. Не потрібно робити його максимально корисним чи розумним.

Luna може запропонувати майже готову фразу. Nemotron може її переформулювати, використати частково або вибрати іншу доречну реакцію.

Мовчання – нормальний результат.

## 8. Практична перевірка

Використай реальні Luna через OMP і Nemotron через LM Studio.

Перевір:

**A. Natural initiative**

Користувач обговорює Skin Creator, залишає незавершену тему й замовкає. Luna пропонує доречне продовження, яке Nemotron вимовляє без нового повідомлення користувача.

**B. Silence**

Після кількох звичайних повідомлень без цікавих незавершених тем персонаж не створює штучних приводів для розмови.

**C. Cancellation**

Luna підготувала жарт, але користувач змінив тему або попросив припинити жарти. Застаріла ініціатива не виконується.

**D. No repetition**

Одна й та сама ідея не запускається повторно після виконання або перезапуску.

**E. Concurrency**

Нове повідомлення користувача надходить саме тоді, коли має початися автономна репліка. Користувач отримує пріоритет, потоки не змішуються.

**F. Recovery**

Перезапуск Runtime зберігає коректну історію, Markdown Context і стан уже виконаних або скасованих ініціатив.

**G. Fast independence**

Nemotron продовжує відповідати без очікування Luna, навіть коли Deep зайнятий.

Виміряй TTFT, витрати додаткових Deep-викликів і вплив на KV cache.

Особливо важливі живі діалоги: перевір, чи ініціатива справді виглядає доречною, а не механічною.

Не додавай великий eval framework або десятки несуттєвих тестів.

Мета – **один простий, робочий цикл самостійної поведінки**, а не універсальна архітектура автономних агентів.

## Definition of Done

**Liac може самостійно вирішити щось сказати, має конкретну причину для цього й природно формулює репліку через Nemotron.**

Luna асинхронно підтримує характер, інтереси та робочий контекст. Runtime забезпечує мінімальну перевірку й безпечне виконання. Nemotron залишається швидким і незалежним.

Персонаж уміє не тільки говорити сам, але й **доречно мовчати**.
